# Product Specification Skill

## Procedure
1. Read `docs/PRODUCT_SPEC.md` and inspect existing behavior.
2. Identify user problem, user type, desired outcome, and non-goals.
3. Write Given/When/Then acceptance criteria, including empty, invalid, and failure states.
4. Identify keyboard, accessibility, persistence, security, and migration impacts.
5. Separate MVP requirements from later ideas.
6. List unresolved decisions; do not invent product-owner preferences.
7. Update the spec only after explaining any scope change.

## Output
- Goal and non-goals
- User stories
- Acceptance criteria
- Edge cases and failure behavior
- Data/security impact
- Open questions
- Suggested tests

## Stop and ask
Ask the user before scope expansion, destructive behavior, external data sharing, or irreversible product decisions.
